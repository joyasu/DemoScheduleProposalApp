# 予定表示・提案計算の設計

## データの流れ

`ContentView` が取得した元の `ScheduleEvent` 配列を `AgendaViewModel.update(events:now:calendar:)` に渡す。

- 日別表示は `ScheduleDay.upcoming` で生成する。終日予定を各日へ展開しても、提案計算の入力には使わない。
- 提案区間は同じ元の予定配列から `ProposalInterval.available` で生成する。選択数・実行可否・実行対象はこの区間配列を共有する。
- `AgendaInput` は予定のIDだけでなく内容を値として保持し、同じSwiftDataオブジェクトを編集した場合も変更を検出する。予定・現在時刻・Calendarが変わったときに派生データを更新する。
- `AgendaDayContent` は通常表示と区間選択時の行を事前生成する。日付および区間の目的地IDによる辞書を用い、各行で全区間を検索しない。
- `AgendaCalendarViewModel` は表示日とヘッダーの週を保持する。予定のある週・今週に加え、最近閲覧した最大12週と現在のヘッダーの週を表示する。古い空の週を除外しても、予定自体は削除しない。

## 日時の仕様

- 週は端末の `firstWeekday` にかかわらず月曜始まり。
- 終日予定は終了日を含む。開始日と終了日が同じなら1日分。
- 終日の保存時は、注入したCalendarのタイムゾーンで開始・終了を日の開始時刻に正規化する。
- 日数の加減算はCalendarを使う。1日を固定の86,400秒として扱わない。
- 編集・日別表示・週生成は同じCalendarを使用する。画面では環境のCalendarを渡し、ContentViewで表示タイムゾーンも合わせる。テストではGregorian Calendarとタイムゾーンを明示できる。
- 終日予定の保存形式は従来どおりDate。タイムゾーン移動時も暦日を固定するための永続化形式変更は行っていない。

## 提案結果

`ProposalGap` は `.planned(Plan)` または `.unavailable(Failure)` を返す。準備時間の注意事項も `Notice` で区別する。文言は `ProposalGapView` が表示時に選ぶため、ロジックのテストは文言ではなく結果の種類と数値を検証する。

休憩は開始・終了・場所をまとめた `Rest`。逆転した日時では初期化できない。準備時間10分、最低休憩時間5分という計算仕様は維持する。

区間計算が通常エラーを投げた場合は、その区間に `.unexpectedFailure` を記録して後続区間を処理する。キャンセル時は失敗表示を作らず終了する。読み込みの識別子により、古い処理の完了が新しい結果や読み込み状態を上書きしない。
